# 유학생 공가 대체 과제 제출 사이트

입국이 늦어져 출석이 어려운 학부 유학생이 과제물을 제출해 공가를 인정받도록, 제출 → 담당교수 승인 →
학과장 최종 확인 → 학사행정 보고 자료까지 한 곳에서 처리하는 사이트입니다.
기획안: 「유학생 공가 대체 과제 제출 사이트 기획안 (초안 v0.1)」

Next.js 14 (App Router) + Tailwind + Supabase(Pro, DB + 비공개 Storage)

## 역할과 흐름

| 역할 | 로그인 | 할 수 있는 것 |
|---|---|---|
| 학생 | 학번 + 생년월일 (명단에 있는 학생만) | 과목·분반별 과제 슬롯(최대 3개) 업로드·교체(마감 전), 상태·반려 사유 확인 |
| 분반 담당교수 | 초대 메일 링크 → 이후 이메일 링크 또는 비밀번호(선택) | 본인 분반 제출 열람, 승인·반려(사유 필수), 미제출·미승인 명단 엑셀, 분반 ZIP |
| 학과장 | 교수와 같음 + **2차 인증(인증 앱) 필수** | 전체 현황, 최종 확인, 보고 자료, 교수·학생 명단 관리, 마감 설정·예외 연장 |

1. 학생 로그인 → 과제 슬롯 확인 → 파일 업로드 (상태 "제출 완료")
2. 담당교수에게 화면 알림 → 열람 후 승인 또는 반려
3. 반려 시 학생에게 사유와 함께 알림 → 마감 전 재제출
4. 분반의 모든 과제 승인 → 학생 상태 "승인 완료"
5. 학과장 최종 확인 (승인 완료 건만 가능, 확인 후에는 학생·교수가 바꿀 수 없음, 취소 가능)
6. 공가 인정 엑셀 다운로드 → 학사행정 전달

|---|---|

| `/staff/login` | 교수·학과장 로그인 (비밀번호 / 로그인 링크 받기 / 비밀번호 재설정) |

| `/prof/sections/[id]` | 미제출·미승인 학생(상단), 제출 목록·파일 보기·승인/반려, 명단 엑셀, 분반 ZIP |
| `/head` | 과목·분반별 승인 진행률, 교수별 미승인 건 강조, 최종 확인, 미제출·미승인 명단, 보고 자료·과목별 ZIP |
| `/head/professors` | 교수 목록(이름·이메일·담당 분반·최근 로그인·상태), 초대/재발송, 로그인·재설정 링크, 분반 배정, 비활성화·재활성화, 초대 미수락 필터, CSV 일괄 등록 |
| `/head/students` | 명단 CSV 업로드(점검 미리보기 → 확인 후 반영), 한 명씩 추가·수정·삭제, 로그인 여부·제출 현황, 공가 주차, 학생별 마감 연장, 잠김 해제 |
| `/head/courses` | 분반별 과제 수(1~3)와 과제 제목 |
| `/head/settings` | 공통 마감일, 교수 로그인 유지 기간, 학생별 총량 한도, 보관 기간 종료 시 원본 일괄 삭제 |
| `/head/audit` | audit_logs 열람 |

## 산출물

| 자료 | 위치 | 권한 |
|---|---|---|
| 공가 인정 엑셀 (과목명, 분반, 학번, 이름, 공가 인정 주차, 제출 과제 수, 승인 교수, 최종 확인일) | `/api/exports/approved` | 학과장 |
| 제출 현황 (학생별 과제 1~3 상태·제출 일시) | `/api/exports/status[?sectionId=]` | 학과장 전체 / 교수 본인 분반 |
| 미제출·미승인 명단 (과목, 분반, 담당교수, 학번, 이름, 미제출·미승인 번호, 반려 사유) | `/api/exports/missing[?sectionId=]` | 학과장 전체 / 교수 본인 분반 |
| 과제 파일 묶음 `과목_분반/학번_이름/학번_이름_과목_과제N.ext` | ZIP 버튼 | 학과장(과목별) / 교수(분반) |

ZIP은 서버가 10분짜리 서명 링크 목록만 만들고 브라우저가 받아 묶습니다(서버 메모리·실행 시간 한도를 피하려는 것).

## 보안·개인정보 처리

- 모든 테이블 RLS ON + 정책 없음 → anon 키로는 아무것도 못 읽음. 서버(service role)만 접근
- 과제 파일은 비공개 버킷 `assignments`(파일당 10MB, PDF·hwp·hwpx·docx). 학생 업로드는 서버가 학생·슬롯·마감·형식·용량을
  확인한 뒤 발급한 **1회용 업로드 링크**로만 가능하고, 업로드 후 서버가 실제 크기를 다시 확인해 확정
- 파일 열람은 5분짜리 서명 링크. 본인/담당교수/학과장만
- 저장 파일 경로는 `수강ID/슬롯/uuid.확장자`, 화면·다운로드 이름은 `학번_이름_과목_과제번호` (Supabase Storage가 한글 경로를 받지 않기 때문)
- 생년월일은 `HMAC-SHA256(BIRTHDATE_PEPPER, 학번:생년월일)`로만 저장. 원본 CSV는 저장하지 않음
- 생년월일은 경우의 수가 적어 대입 공격 위험 → 학생·교수 로그인 5회 실패 시 15분 잠금(학과장이 해제 가능)
- 학과장: 2차 인증 전 세션은 10분, 2차 인증을 마쳐야 관리 화면 접근
- 메일 링크는 해시만 저장, 1회용, 초대 7일 / 로그인 30분 / 재설정 1시간. 링크 페이지가 POST로 소모하므로 메일 보안 검사기가 미리 열어도 소모되지 않음
- 계정 등록, 분반 변경, 비활성화, 링크 발송, 명단 등록, 승인·반려, 최종 확인, 설정 변경, 다운로드 등은 모두 `audit_logs`에 기록
- 입국 관련 정보는 받지도 저장하지도 않음

## 설치

1. Supabase **Pro** 프로젝트 생성 (무료 요금제는 1주 미사용 시 일시 정지 위험). 리전·개인정보 처리 방침은 학교 정책과 함께 확인
2. SQL editor에서 `supabase/schema.sql` 실행 (다시 실행해도 안전)
3. `.env.example` → `.env.local` 복사 후 채우기
   - `SESSION_SECRET`, `BIRTHDATE_PEPPER`: `openssl rand -base64 32` 로 각각 생성. **`BIRTHDATE_PEPPER`는 바꾸면 학생 전원이 로그인할 수 없음**
   - `APP_URL`: 배포 주소 (메일 링크에 사용)
   - `RESEND_API_KEY`, `EMAIL_FROM`: 메일 발송용(선택). 비우면 학과장 화면에 링크가 표시되어 직접 전달
4. `npm install`
5. 첫 학과장 계정: `npm run create-head -- 이메일 이름` → 출력된 초대 링크로 로그인 → 인증 앱 등록 → 비밀번호 설정(선택)
6. `npm run dev` (배포는 Vercel 등, 환경변수 동일)

## 기획안 열린 질문에 대한 1차 버전 처리

| 열린 질문 | 1차 버전 |
|---|---|
| 학생별 총량 한도 | 설정값(`/head/settings`), 기본 "제한 없음". 파일당 10MB는 고정 |
| 마감일 | 설정값 하나(전 과목 공통). 학과장이 학생·과목별로 예외 연장 |
| 공가 최대 주차·과제 수 기준 | 과제 수는 분반별 1~3 설정, 공가 인정 주차는 명단 CSV `공가주차` 열 또는 학생 명단 화면에서 입력 (학칙 확인 후 값만 채우면 됨) |
| 로그인 유지 기간 | 설정값, 기본 30일 |

## 아직 하지 않은 것

- 교수에게 **메일** 알림 (지금은 화면 알림만. 제출이 몰리면 메일이 너무 많아져, 하루 1회 요약 메일이 적당해 보임)
- 보관 기간 자동 삭제 (지금은 학과장이 설정 화면에서 직접 실행)
- 실제 Supabase 프로젝트에 연결한 종단 테스트 (스키마는 PostgreSQL 16에서 실행 확인, 빌드·권한 라우팅·입력 파싱만 확인됨)
